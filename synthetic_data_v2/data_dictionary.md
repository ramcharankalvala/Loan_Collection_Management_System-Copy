\# Synthetic Loan Collection Dataset – Data Dictionary



\## 1. Overview



This document describes the fields in the synthetic loan collection dataset generated by `generate\_dataset.py`.



\- Random seed: `20261022`

\- Total customers: 10,000

\- Total accounts: 10,000

\- Total loans: 10,000

\- Total installments: 30,000

\- Data format: CSV

\- Database: MySQL (`loan\_collection\_synthetic`)



All records are synthetic and do not represent real customers.

\## 3. Primary Keys and Relationships



\- `customers.customer\_id` – Primary key.

\- `accounts.account\_id` – Primary key.

\- `loans.loan\_id` – Primary key.

\- `installments.installment\_id` – Primary key.

\- `payments.payment\_id` – Primary key.

\- `delinquency\_snapshots.snapshot\_id` – Primary key.

\- `collection\_cases.case\_id` – Primary key.

\- `contact\_attempts.attempt\_id` – Primary key.

\- `promises\_to\_pay.promise\_id` – Primary key.

\- `risk\_indicators.loan\_id` – Primary key.

\- `contact\_preferences.customer\_id` – Primary key.



Foreign key relationships connect customers, accounts, loans, installments, payments, collection cases, contact attempts, and promises.



`ground\_truth.record\_id` is polymorphic: it refers to a record in different entity tables depending on the anomaly. It is therefore not defined as a conventional foreign key.



\## 4. Data Quality and Validation



The generator checks:



\- Primary-key uniqueness.

\- Required foreign-key references.

\- Expected loan and installment counts.

\- Financial amount consistency.

\- Delinquency arithmetic.

\- Reproducibility using a fixed random seed.



Five intentional edge cases are labelled separately in `ground\_truth.csv`. These are deliberate test scenarios, not accidental data-generation errors.



\## 5. Important Notes



\- All data is synthetic.

\- Risk and priority scores are generated using rules, not a trained machine-learning model.

\- `ground\_truth.csv` is intended for evaluation and should not be used as an input feature when building predictive models.

\- The generated data is intended for development, testing, analytics, and collection workflow evaluation.

\- Refer to `generate\_dataset.py` for generation logic and `output/schema.sql` for MySQL definitions.
